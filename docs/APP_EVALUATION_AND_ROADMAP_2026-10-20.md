# StreamNest Downloader 앱 평가 및 개선 로드맵

> 작성일: 2026-10-20  
> 검토 대상: GitHub main 브랜치, 검토 시점 HEAD 4793da63fa5b40eefea0cbde36c18e5680da5bb1  
> 현재 기준: StreamNest Downloader 0.7.8 (단일 다운로드 최종 보존 버전)  
> 검토 방식: 저장소의 소스·XAML·문서·단위/통합 테스트 코드에 대한 정적 검토. Windows에서 직접 실행하거나 전체 테스트를 돌린 결과가 **아님**.  
> 원칙: 0.7.8 태그·Release·보관 파일은 변경하지 않고, 후속 기능은 새 버전 및 별도 작업 브랜치에서 개발한다.

## 1. 결론

**단일 영상의 추출·검증·다운로드 신뢰성을 깊이 다듬은 앱이다. 다음 투자 대상은 새로운 사이트 추가보다 작업 관리, 장애 복구, 테스트 자동화, 개인정보 보호다.**

- **현재 잘한 것:** 치지직/YouTube/SOOP/일반 영상 경로, 브라우저 분석 폴백, 서비스별 세션 분리, SOOP 분할 VOD 공통 화질 검사, 검증 전 임시 저장, 기존 파일 미덮어쓰기, 실패 조각 격리, 경고 저장 구분.
- **한계:** 기본 UI가 한 번에 하나의 작업만 다룬다. 다운로드 목록·영속적 작업 이력·재실행 후 작업 복원 모델이 없다. 에러나 완료 결과를 사후에 추적하기 어렵다.
- **구조적 부담:** MainWindow 코드비하인드에 URL 분석·로그인·UI 상태 전이·다운로드·취소·로그가 집중돼 있다. 대기열을 그대로 덧붙이면 회귀 위험이 커진다.
- **배포/안전:** 외부 엔진 버전·해시·고지·검증이 신경 써서 구성돼 있지만, 저장소에서 자동 CI 워크플로를 확인하지 못했다. 공개 임의 URL의 DNS 검사와 실제 엔진/브라우저 요청 간 경계도 보안 검토가 필요하다.

## 4. 내가 설계한다면: v0.8의 제품 방향

### A. "다운로드 창"에서 "다운로드 작업 관리자"로

- 최상단: URL 다중 붙여넣기, 탭/플랫폼 자동 인식, '대기열에 추가'.
- 중앙: 각 작업의 썸네일·제목·플랫폼·화질·저장 경로·진행 단계·속도/ETA·상태 배지.
- 하단: 선택 작업의 상세 상태와 오류 해결 버튼. 기술 로그는 접어 놓되 익명화 복사 가능.
- 작업 상태: Pending → Analyzing → Ready → Downloading → Verifying → Completed / CompletedWithWarnings / Failed / Canceled / Interrupted.
- 자동 실행은 **직렬 1개**로 시작한다. SOOP 분할 VOD와 HLS 동시 조각 수신 자체가 이미 병렬이므로 상위 작업까지 여러 개 병렬화하는 것은 2차 과제다.
- 현재 앱의 '취소 후 조각 보관'은 실제 일시정지와 다르다. 버튼은 '중단(조각 보관)'과 '취소·삭제'로 명확히 나눈다.

**정량적 완료 조건:** 20개 URL을 넣어도 작업이 서로 섞이지 않고 정확히 하나만 다운로드 중. 중간 작업 취소·실패가 다른 작업에 영향 없음. 같은 제목/다른 화질/다른 영상 ID의 파일 혼동 0건.

### B. 가장 작은 구조 변경으로 리팩터링

전체 MVVM 재작성보다, 서비스 계층을 먼저 추출하고 메인 윈도우를 가볍게 만든다.

서비스/플러그인별 어댑터 통합은 나중에 필요할 때 실시한다. 첫 릴리스에서 추출 엔진과 미디어 검증을 동시에 전면 교체하지 않는다.

### C. 데이터/프로필 호환성

- v0.7.8이 사용하는 ChzzkLocalDownloader/ChzzkDownloader 하위 데이터는 그대로 둔다.
- 새 작업 대기열·상태 파일은 별도 버전 네임스페이스에 저장한다. 이전 설정이 필요한 경우 **복사하여 이행**하며 원본을 수정/삭제하지 않는다.
- 저장 파일은 임시 파일 작성 → flush → 원자적 교체가 가능한 흐름을 사용하고, JSON 스키마 버전과 복구 정책을 명시한다. 데이터가 복잡해지는 시점에 SQLite 도입 여부를 판단한다.
- 세션은 서비스별로만 사용하고, 공개 일반 웹 작업에 플랫폼 인증 쿠키를 전달하지 않는 불변식을 테스트로 고정한다.
- 기존 '영상 ID/화질 확인 후 완료', 실패 시 격리, 검증 전 임시 저장, 전체 파일 디코딩 생략 정책은 변경하지 않는다.

### D. 신뢰할 수 있는 완료 화면

- **완료**: 조각 누락 감지 없음, 필수 스트림/화질 등 기본 검사를 통과했다는 의미.
- **완료 · 확인 권장**: 길이 불일치 또는 길이 측정 불가 등 경고 저장.
- **실패**: 파일을 최종 다운로드 폴더에 완료 파일로 게시하지 않음.
- 어느 경우에도 '파일 전체를 프레임 단위로 완전 검사했다'라고 표현하지 않는다.
- 선택 기능으로 '저장 파일 재생', '폴더 열기', '검사 경고 보기'를 각 작업에서 제공한다.

3. 서비스별 URL·에러·예외·로그 복사의 익명화 테스트 작성 후 공통 마스킹.
4. 일반 웹 URL의 초기 요청·리다이렉트·HLS 하위 요청·브라우저 캡처의 네트워크 경계 시험.

**완료 기준:** PR마다 오프라인 테스트 결과 기록, 민감 문자열 노출 회귀 0, 실계정 시험 자동 실행 금지. 확인된 보안 경계 문제는 대기열보다 먼저 해결.

### 1단계 — v0.8.0 직렬 큐 MVP

1. DownloadJob + 상태 전이/JobId 모델.
2. DownloadCoordinator에서 기존 AnalyzeAsync/DownloadAsync를 직렬 실행.
3. 다중 URL 추가/중복 안내/작업별 화질·폴더/작업별 취소 및 재시도.
4. 테스트: 20개 작업 큐, 오류 격리, 동일 이름의 서로 다른 영상, 로그인 필요한 항목, 경고 완료, 취소 후 조각 보관·삭제.

**완료 기준:** 실제 전송은 한 번에 하나이며 다른 작업 상태를 덮어쓰지 않음. 기존 단일 작업 회귀 테스트도 통과.

### 2단계 — v0.8.x 복구/편의성

1. 새 경로에 큐/이력 영속 저장 및 앱 재시작 복구.
2. 작업별 실패 원인/권장 조치, 서비스별 로그아웃, 로그 익명화 내보내기.
3. 이전 0.7.8 설정·로그인 프로필 호환성 점검, 필요시 복사 마이그레이션.

**완료 기준:** 강제 종료 후 미완료 작업은 자동 '완료'로 표시하지 않음; Interrupted로 표시하고 재개는 사용자가 결정. 이전 버전 실행/로그인 정상.

### 3단계 — v0.9 후보 (성능 관찰 후)

- 상위 다운로드 동시성 2개 이상, 우선순위 변경, 백그라운드/트레이, 선택적 속도 제한, 작업 이력 검색.
- 서비스 특성별 rate limit, 로그인 갱신, 메모리/디스크 사용량을 먼저 계측한다.
- DRM 우회·접근권한 우회·외부 브라우저 자격증명 수집은 기능 범위에서 제외한다.

## 6. 반드시 추가할 회귀 테스트

| 분류 | 시나리오 | 기대값 |
| --- | --- | --- |
| 작업 분리 | A가 인증 실패해도 B의 공개 영상은 계속 | 세션/URL/임시 폴더가 섞이지 않음 |
| 취소 | A의 다운로드 취소 후 B 실행 | A만 중단·격리; B 정상 |
| 재개 | 취소/재시작 뒤 동일 영상·화질 재개 | 부분 조각을 안전하게 재사용; 잘못된 체크포인트는 격리 |
| 데이터 호환 | 0.7.8 프로필/설정이 있는 상태로 0.8 실행 후 0.7.8 재실행 | 원본 로그인·설정 손상 없음 |
| 미디어 무결성 | 0바이트, HTML 응답 조각, 음성 누락, 화질 미일치 | 완료 파일로 게시하지 않음 |
| 경고 | 길이 차이, 길이 측정 불가 | 경고 완료와 일반 완료가 구별됨 |
| URL 안전 | 리다이렉트·DNS 변조 시뮬레이션, 하위 HLS 경로, 차단해야 할 내부망 대상 | 요청 단계마다 지정 정책 통과, 차단 시 안전 종료 |
| 로그 | 합성 서명 URL, 인증 헤더, 쿠키, 웹 프로필 경로, 예외 문자열 | 사용자 복사/진단에도 민감정보가 남지 않음 |
| 플랫폼 | 치지직 클립, SOOP 캐치/분할, YouTube 개별 영상, 일반 웹 | 각각 기존 파일 동일성/화질 검증 유지 |
| 국제화 | 한글 경로·이모지/긴 제목·경로 길이 제한 | 파일명/작업 상태 혼동·오염 없음 |
| UI | 완료/실패/경고/중단 상태를 스크린리더·키보드로 확인 | 상태 텍스트와 동작이 일치 |

외부 플랫폼 및 실계정 통합 시험은 명시적으로 켜는 별도 경로에서만 실행한다. 일반 PR 체크에는 합성 시험 자료를 사용한다.

## 7. 의도적으로 하지 않을 것

- **0.7.8 릴리스/태그를 덮어쓰는 수정**
- 단일 버전에서 큐·동시성·계정관리·엔진교체를 한꺼번에 넣는 빅뱅 리팩터링
- 보존된 로그인 프로필/기존 사용자의 쿠키를 자동 삭제하거나 외부 웹 작업으로 전달
- 일반 웹 캡처에 임의 확장 프로그램·로그인 우회·CAPTCHA/DRM 우회를 도입
- 테스트 실행 없이 '모든 회귀 테스트 통과'라고 표시
- 단순 ffprobe 기본 검사 결과를 전체 미디어 무결성 보증으로 표현

## 8. 즉시 착수 추천 TOP 3

1. **P0 — Windows CI + 민감정보 로그 마스킹 회귀:** 변경해도 안전한 개발 토대를 만든다.
2. **P1 — DownloadJob/DownloadCoordinator 직렬 대기열:** 사용자 체감이 가장 큰 기능을 기존 엔진 재사용으로 제공한다.
3. **P1 — 큐/이력 영속화 및 안전한 재실행 복구:** 단일 다운로드 도구를 신뢰할 수 있는 작업 관리 앱으로 만든다.

**최종 권장:** v0.8은 '플랫폼을 더 많이 뚫는 앱'이 아니라 '현재 잘 다운로드되는 영상을 여러 개 안전하고 편하게 관리하는 앱'으로 정의한다.
