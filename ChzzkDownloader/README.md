# StreamNest 다운로더

Windows에서 치지직과 YouTube 영상을 한 곳에 저장하는 독립형 GUI 앱입니다. 공개 영상은 로그인 없이 처리하고, 계정 인증이 필요한 영상에서 내장 WebView2 창을 엽니다.

## YouTube 지원

- `youtube.com/watch?v=...`, `youtu.be/...`, Shorts, Embed, Live 주소를 지원합니다.
- 재생목록 주소는 단일 영상 URL로 변환한 뒤 사용해야 하며, 재생목록 전체 다운로드는 비활성화되어 있습니다.
- YouTube 로그인·멤버십·연령 제한 영상은 앱의 WebView2 로그인 후 계정 권한 범위에서 지원합니다. DRM·봇 검증·추가 인증 토큰이 필요한 영상은 지원하지 않을 수 있습니다.
- 코덱스 내부 브라우저나 다른 브라우저의 로그인 세션은 앱으로 가져오지 않습니다. 제한 영상은 앱의 `로그인하고 계속` 창에서 로그인해야 합니다.
- 다운로드는 본인이 권리를 갖거나 다운로드가 허용된 콘텐츠에만 사용하세요. YouTube 및 저작권자의 이용 조건이 우선합니다.

## 사용법

### 일반 웹 영상 (0.6.6)

- **일반 영상** 탭에 공개 HTTPS 웹페이지·MP4·HLS 주소를 입력합니다. 페이지에서 최대 20개를 분석하고, 선택한 영상 하나만 저장합니다.
- 일반 영상 분석과 다운로드에 `--impersonate chrome` 및 `--extractor-args generic:impersonate`를 자동 적용합니다. 초기 페이지뿐 아니라 HLS 재생목록·하위 목록·영상 조각에도 번들 yt-dlp의 브라우저 호환 전송을 사용합니다. 분석 결과 재사용 시에도 유지되며, 치지직·YouTube 요청에는 적용하지 않습니다. 일부 서버에서는 속도나 안정성에 영향을 줄 수 있습니다.
- 난독화에서 HLS 주소를 찾았지만 서버가 거부하면 접근 거부(HTTP 401/403)로 표시합니다. 재생목록 요청 실패를 `Unsupported URL`로 오인하지 않으며, 다른 정상 영상 후보가 있으면 계속 분석합니다.
- 이 옵션은 일부 HTTP 403 호환성 문제에 도움이 되지만 모든 Cloudflare 인증, CAPTCHA, DRM 또는 로그인이 필요한 사이트를 지원한다는 뜻은 아닙니다. 브라우저 쿠키를 자동으로 가져오지 않습니다.
- 치지직·YouTube 탭의 로그인·쿠키 분리는 유지됩니다. 일반 웹 요청에는 해당 플랫폼의 로그인 쿠키를 전달하지 않습니다. 파일 검증과 안전한 최종 저장은 모든 탭에 공통 적용됩니다.
- 공개 시험 자료: [HTML5 영상 예제](https://www.w3schools.com/html/html5_video.asp), [Mux HLS 시험 스트림](https://test-streams.mux.dev/).

#### Packer/HLS 보완 분석

- 일반 추출기 결과와 함께 Packer 형태의 인라인 스크립트도 해석합니다. 예고편 하나를 찾았다고 추가 탐색을 중단하지 않습니다. `eval`이나 브라우저 JavaScript는 실행하지 않으며, 문자열·기호 치환 후 HLS 주소 리터럴을 찾습니다.
- 같은 경로의 명시적인 `90p/180p` 등의 화질 변형, 또는 비디오 트랙 주소가 겹치는 마스터 플레이리스트는 한 영상의 화질 목록으로 묶습니다. 공통 음성 트랙만으로 서로 다른 영상을 합치지 않습니다.
- 분석한 스트림과 요청 헤더는 메모리에서 보존하고 다운로드에 재사용합니다. 일부 401/403/404/410·만료 오류가 발생하면 페이지를 한 번 갱신해 영상 ID와 선택한 화질을 확인한 뒤 재시도합니다. 영상이 바뀌었거나 화질이 사라졌다면 중단합니다.
- 영상 ID에서 알려진 임시 서명·토큰 매개변수만 제외합니다. `video=1` 같은 내용 식별 매개변수는 유지합니다. URL 경로 자체가 만료 토큰으로 바뀌거나 알 수 없는 매개변수가 바뀌면 자동 갱신되지 않을 수 있습니다.
- Referer/Origin은 실제 페이지에서 생성해 HLS 요청에 전달합니다. 다른 Origin에는 페이지의 쿼리 매개변수를 Referer로 보내지 않습니다. 플랫폼 로그인 쿠키나 스크립트가 지정한 임의 헤더는 가져오지 않습니다.
- 다른 서버에서 페이지 경로까지 요구하는 경우 **HLS 호환 요청: 다른 영상 서버에 페이지 경로 전달**을 선택한 뒤 다시 분석할 수 있습니다. 기본값은 꺼짐이며, 켜도 다른 서버에 쿼리·로그인 쿠키는 전달하지 않습니다. 이 옵션은 Packer/HLS 보완 분석 경로에 적용됩니다.
- 보완 분석 한도: 페이지 2 MiB, 스크립트 256 KiB, 해석 결과 1 MiB, 기호 4,096개, 블록 8개, 중첩 2단계, HLS 후보 10개입니다. 앱의 공개 HTTPS 주소 입력 검사는 유지됩니다.
- 모든 JavaScript 난독화나 런타임 계산을 지원하는 기능은 아닙니다. DRM·실시간 영상의 기존 제외 정책도 유지됩니다.
- 시험은 직접 생성한 4초 영상의 90p/180p HLS와 로컬 Packer 페이지로 수행합니다. 로컬 시험은 내부 테스트 생성자에서 해당 시험 서버만 허용하며, 배포 앱에 로컬 주소 허용 옵션을 추가하지 않습니다.

#### 모든 탭의 완료 판정 (0.6.5)

- 0.6.6부터 예상 영상 길이는 영상 트랙의 길이와 우선 비교합니다. 트랙 길이가 없는 컨테이너에서만 전체 파일 길이를 대신 사용하며, 기존 허용 오차를 늘리지 않습니다. 음성 정렬·패딩에 따른 잘못된 실패와 긴 음성이 짧은 영상을 가리는 경우를 구분합니다.

- 조각 다운로드가 재시도 후에도 실패하면 건너뛰지 않고 중단합니다. 조각은 검증까지 보관하므로 기존보다 임시 디스크 공간이 더 필요할 수 있습니다.
- HTTP 200으로 반환된 빈 조각·평문 오류 응답을 검사하고, 결과 파일의 영상·필요한 음성·선택 화질·예상 길이 및 전체 디코딩을 확인합니다. 검증 단계도 취소할 수 있습니다. 이는 모든 형태의 내용 손실을 수학적으로 보장하는 검사는 아닙니다.
- 검증 전 파일은 임시 작업 폴더에만 둡니다. 검증을 통과한 파일만 저장 폴더로 옮깁니다. 선택 화질을 아는 경우 파일명에 `[720p]`처럼 표시하며, 같은 이름의 기존 파일은 덮어쓰지 않고 번호를 붙입니다. 다른 화질을 다시 받아도 이전 파일을 완료 결과로 재사용하지 않습니다.
- 일반 웹의 주소 갱신으로 영상 목록 순서가 바뀌어도 현재 작업의 임시 폴더는 유지합니다. 따라서 취소 후 삭제는 재시도의 실제 파일까지 정리합니다. 이전 버전에서 이미 남은 고아 폴더를 임의로 일괄 삭제하지는 않습니다.
- 엔진 오류·검증 실패 자료는 해당 작업 내부의 `failed-attempt-...` 폴더에 격리해 잘못된 이어받기 상태가 재사용되지 않게 합니다. 자동 재시도는 새 `active` 폴더에서 시작합니다. 격리 자료는 해당 작업이 성공하거나 취소 후 삭제를 선택하면 함께 정리하며, 실패 상태로 남겨 두면 보존됩니다.
- 스트림 토큰이 들어갈 수 있는 임시 요청 JSON은 각 시도 종료 시 삭제하며 설정·로그에 기록하지 않습니다. 강제 프로세스 종료/정전에서는 임시 파일이 남을 수 있으므로 작업 폴더를 민감한 자료로 취급하세요.

### 치지직 · YouTube

1. `StreamNestDownloader.exe`를 실행합니다.
2. 시작 시 표시되는 **도구 정상** 상태를 확인합니다. 문제가 있으면 이 버튼을 눌러 상세 진단을 다시 볼 수 있습니다.
3. `https://chzzk.naver.com/video/...` 주소를 붙여넣고 **영상 확인**을 누릅니다.
4. 원하는 화질과 저장 폴더를 선택한 뒤 **다운로드**를 누릅니다. 최초 기본 저장 폴더는 실행 파일과 같은 위치의 `Archive`이며, 새 버전 폴더로 교체하면 해당 버전의 `Archive`로 자동 전환됩니다.
5. `로그인 필요`가 표시된 영상만 **로그인하고 계속**을 누릅니다. 내장된 해당 서비스 페이지에서 로그인과 필요한 본인 인증을 마친 뒤 **세션 확인**을 누릅니다. 가져온 세션은 실제 영상 분석에 성공해야 확인된 것으로 표시됩니다.
6. 로그인 세션을 가져온 뒤에는 메인 화면 오른쪽 위의 **로그아웃**으로 앱에 연결된 서비스 세션을 제거할 수 있습니다.

다운로드 중 **취소**를 누르면 이번 작업의 임시 조각 삭제, 이어받기용 보관 또는 다운로드 계속 중에서 선택할 수 있습니다. 앱 창을 닫을 때도 진행 중인 작업을 그대로 끊지 않고 같은 확인 절차를 거칩니다. 보관을 선택하면 같은 폴더·화질로 다시 시작할 때 이어받기를 시도합니다. 삭제를 선택하면 다운로드 프로세스 종료 후 일시적인 파일 잠금이 풀릴 때까지 제한된 횟수로 정리를 재시도합니다.

상세 작업 기록은 기본적으로 접혀 있으며 오류 진단이 필요할 때 펼치거나 클립보드로 복사할 수 있습니다.

## 설계

- WPF 기반 Windows 앱
- WebView2의 별도 로컬 프로필을 제한 영상에서만 사용
- `yt-dlp`가 치지직·YouTube 영상 정보와 미디어 조각을 처리
- 치지직 DASH 매니페스트가 `sourceURL`을 생략하고 바이트 범위만 제공해도 번들 호환성 플러그인이 표준 트랙과 범위 기반 트랙을 함께 파싱해 실제 화질 목록을 유지
- 치지직에서는 느린 단일 연결 파일보다 조각형 DASH를 우선해 최대 32개 조각을 병렬로 받음
- `FFmpeg`/`ffprobe`가 미디어 정보를 검사하고 영상·음성을 MP4로 병합하거나 무손실 리먹스
- `yt-dlp`가 보고하는 실제 백분율·조각 수·속도·남은 시간을 한 번의 전체 진행률로 표시
- 시작 시 `yt-dlp`·FFmpeg·ffprobe 실행 여부, WebView2, 저장/임시 폴더 쓰기 권한과 여유 공간을 자동 점검
- 모든 탭에서 조각 누락 중단·미디어 정보·전체 디코딩 검증 후에만 완료로 표시. 전체 검증 동안 시간이 더 걸릴 수 있으며 취소 가능
- 로그인 쿠키는 현재 서비스의 재생 요청에 필요한 Secure 쿠키만 선별하며, 현재 사용자와 SYSTEM만 읽을 수 있는 `%LOCALAPPDATA%\ChzzkLocalDownloader\Temp`의 임시 파일로 전달하고 각 작업 종료 직후 삭제
- 비정상 종료로 남은 쿠키 파일은 소유 프로세스가 종료된 것을 확인한 뒤 다음 실행에서 정리
- 로그인 창은 허용된 HTTPS 치지직·YouTube·Google 로그인 주소만 내부에서 열고 현재 Origin을 항상 표시
- 비밀번호·쿠키 값은 앱 로그에 기록하지 않음
- 저장 폴더 설정과 WebView2 로그인 프로필은 `%LOCALAPPDATA%\ChzzkLocalDownloader`에 저장

메인 화면의 **로그아웃** 또는 내장 로그인 창의 **저장된 세션 삭제**를 누르면 메모리 쿠키와 WebView2 프로필의 쿠키·검색 기록을 삭제합니다.

## 빌드

Windows 10/11 x64와 .NET SDK 10이 필요합니다.

회귀 테스트:

```powershell
dotnet test ..\ChzzkDownloader.Tests\ChzzkDownloader.Tests.csproj -c Release
```

로컬 통합 테스트에서는 실제 HTTP 응답을 WPF 이미지로 디코딩하고 썸네일 UI의 성공·실패 상태를 확인합니다. 실계정·외부 네트워크 테스트는 기본 실행에서 건너뜁니다.

Packer/HLS 시험은 `PackedHlsIntegrationTests`에서 실제 번들 엔진으로 실패 재현, 두 화질 저장, 헤더 전달, 전체 디코딩을 검증합니다. 문자열 디코더의 별도 테스트는 개발용 Python과 yt-dlp가 설치된 환경에서 `python -B -m unittest discover -s ..\PluginTests -v`로 실행합니다. 배포 앱에는 별도 Python 설치가 필요하지 않습니다.

```powershell
dotnet test ..\ChzzkDownloader.IntegrationTests\ChzzkDownloader.IntegrationTests.csproj -c Release
```

공개 YouTube 실네트워크 분석 테스트:

```powershell
$env:STREAMNEST_RUN_NETWORK_TESTS = '1'
$env:STREAMNEST_YOUTUBE_PUBLIC_URL = 'https://www.youtube.com/watch?v=테스트영상ID' # 생략 시 기본 공개 영상
dotnet test ..\ChzzkDownloader.IntegrationTests\ChzzkDownloader.IntegrationTests.csproj -c Release --filter 'Category=Network'
```

WebView2 실제 로그인과 멤버십·연령 제한 테스트는 먼저 앱의 `로그인하고 계속` 창에서 해당 YouTube 계정으로 로그인한 뒤 실행합니다. 테스트는 코덱스 내부 브라우저가 아니라 앱의 `%LOCALAPPDATA%\ChzzkLocalDownloader\WebView2Profile`을 사용하며 쿠키 값은 출력하지 않습니다.

```powershell
$env:STREAMNEST_RUN_AUTH_TESTS = '1'
$env:STREAMNEST_YOUTUBE_MEMBERS_URL = 'https://www.youtube.com/watch?v=멤버십영상ID'
$env:STREAMNEST_YOUTUBE_AGE_URL = 'https://www.youtube.com/watch?v=연령제한영상ID'
dotnet test ..\ChzzkDownloader.IntegrationTests\ChzzkDownloader.IntegrationTests.csproj -c Release --filter 'Category=AuthenticatedWebView2|Category=RestrictedYouTube'
```

멤버십 테스트 URL은 로그인한 계정이 실제로 시청 권한을 가진 영상이어야 합니다. 실계정 테스트를 실행하지 않을 때는 관련 환경 변수가 없어도 전체 테스트가 실패하지 않습니다.

배포 패키지 생성:

```powershell
.\Publish.ps1
```

결과는 프로젝트 버전을 포함한 `dist\StreamNestDownloader-버전-win-x64` 폴더와 같은 이름의 ZIP으로 생성되며, ZIP의 SHA-256 파일도 함께 만들어집니다. 배포 폴더의 `StreamNestDownloader.exe`를 실행하면 되며 .NET 런타임은 별도로 설치하지 않아도 됩니다. 로그인 창에는 Microsoft Edge WebView2 Runtime이 필요하며, 공개 영상 다운로드는 WebView2가 없어도 사용할 수 있습니다.
